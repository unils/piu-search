# 画面と操作

2026-10-27 の設計（画面の状態とセッションは 2026-11-14、R5 で更新）。見た目の細部は M3 でスクリーンショットを作って詰める。

## 方針

- 開いたらすぐ打てる。キーボードは自動で出す
- 片手で使える。**検索窓は画面の下**（要件 U8・T3）。設定で上にも置ける
- 最も一致するアプリを、親指と検索窓に一番近い位置（検索窓のすぐ上）に置く。結果の一覧は下から上へ並べる
- 確定キー（IME の「検索」「実行」）で、一番上の候補（検索窓のすぐ上の候補）を開く
- 広告を出さない（U7）。通信もしない

## 検索画面

「ちず」と打ったときの画面を、上から順に書く。

| 位置 | 表示 |
|---|---|
| 画面の上部 | （結果が少ないときは空く） |
| 2 番目 | Yahoo!マップ　ジャンル: 地図 |
| 1 番目（検索窓の直上） | Google マップ　ジャンル: 地図（起動の回数が多いので上） |
| 検索窓 | ちず ✕ |
| 画面の下部 | キーボード |

- 1 行: アイコン・アプリ名・（必要なら）出た理由。理由は名前で一致しなかったときだけ小さく出す（「ジャンル: 地図」「学習」「読み: のりかえ」）。なぜ出たかがわかると、誤りに気づきやすく、学習を信用しやすい
- このアプリ自身は結果に出さない
- 検索語が空のとき: 「最近使ったアプリ」（4 件）と「よく使うアプリ」（8 件）を見出しつきで並べる。記録がなければ探し方の案内を出す。確定キーでは何も開かない（意図しない起動を避ける）
- 出た理由の書式: 「読み: …」「ローマ字: …」「別名: …」（別の言語の名前）「パッケージ名: …」「ジャンル: …」。名前で一致したときは出さない
- 一致がないとき: 「見つかりません」と、大きめの「すべてのアプリ」のボタンを出す

## すべてのアプリ

検索で出なかったアプリを学習させるには、全アプリから選べる必要がある（2026-10-27 のメンテナの提案）。

- 検索窓の横に「すべてのアプリ」のボタンを常に置く。結果の一覧の端に置くと、下から並べる一覧では画面の上端になり、親指が届かないため
- 押すと、全アプリを名前の順に並べる。英字で始まる名前は A〜Z の順で先にまとめ、かな・漢字の名前は**読みの五十音順**に並べる（漢字の名前も読みで並べられるのは、索引に読みがあるから）。右端に頭文字の索引（A〜Z、あ・か・さ…）を置き、なぞって飛べるようにする
- 検索語は検索窓に残したまま一覧を出す。ここでアプリを開くと、その検索語とアプリを学習する（[learning.md](learning.md) の救済）。学習と起動の記録を保存してから開き、成功した場合だけ Toast で短く知らせる。「「おかね」で PayPay を出すようにしました［取り消す］」は次に検索画面を開いたときに出す（[learning.md](learning.md#規則)）。何を覚えたかがわかり、誤りは取り消せる
- 検索窓に文字を打つと、検索の結果に戻る。「戻る」でも戻る。一覧を出している間はキーボードを下げ、確定キーでは何も開かない
- 一覧は上から読む向き（A が上）。数字・記号・ほかの文字で始まる名前と、読みのわからない漢字の名前は、最後の「#」にまとめる。名前の頭の記号は飛ばして見る（`+メッセージ` は「ま」の行）
- 五十音順は、濁点と小さい仮名を除き、長音を前の字の母音に置き換えた形で比べ、同じなら元の形で比べる（M3-02）

## 仕事用プロファイル

仕事用プロファイル（同じ端末の中で、仕事のアプリとデータを分けて持つ OS の仕組み）があるときだけ、検索窓の上に「個人用｜仕事用」の切り替えを出す（2026-10-27 のメンテナの希望）。

- 新しく開いたとき・入口から呼び直したときは「個人用」。回転などの構成の変更では選んでいるタブを保つ。検索の対象はそのとき選んでいるプロファイルのアプリだけ
- 個人用で一致がなく、仕事用に一致があるときは「仕事用に 2 件」と知らせ、押すと切り替わる
- 仕事用の結果のアイコンには、OS の標準の印（かばん）を付ける
- 仕事用アプリを一時停止しているときは、そのことを表示する。一時停止中のアプリを開こうとすると、OS が「仕事用アプリを再開しますか」の確認を出し、再開したらそのまま開く（AOSP の `ActivityStartInterceptor.interceptQuietProfileIfNeeded`）。このアプリの側で再開の操作はできない（既定のホームアプリにしか許されない）。確認で取り消したかを受け取れないため、一時停止中への要求は起動回数と学習に記録しない（[learning.md](learning.md#アプリを開くときの保存r22026-11-14)）
- 自分以外のプロファイルは、すべて仕事用として扱う（仕事用かを見分ける API はシステムのアプリにしか使えない。OEM の複製のプロファイルなども「仕事用」にまとまる）
- 学習はプロファイルごとに分ける（個人用の LINE と仕事用の LINE は別のアプリとして扱う）
- GrapheneOS の「別のユーザー」とプライベートスペースのアプリは、OS の仕様で見えない

## 長押しのメニュー

- アプリ情報（OS の設定画面のそのアプリのページ）
- この語では出さない（学習の R4）
- この語での学習を消す（学習で出ている場合）
- 学習の一覧（どの行にも出す。誤って覚えた行からすぐ直しに行けるので、設定画面ができた後も残す。一覧は検索の画面と同じタスクに積み、「戻る」で検索の画面に戻る）

アンインストールは入れない（`REQUEST_DELETE_PACKAGES` の権限が要る）。アプリ情報の画面から行える。

## 呼び出し

| 入口 | 動き |
|---|---|
| ランチャーのアイコン | 検索画面を開く |
| デジタルアシスタント | 設定で既定のアシスタントにすると、画面の隅からのスワイプや電源ボタンの長押しで開く（Pixel での動作は実機で確認する） |
| クイック設定タイル | 通知の領域を下ろして開く |

初回の起動時に、デジタルアシスタントとタイルの設定の仕方を 1 枚で案内する（OS の設定画面を開くボタン付き）。強制はしない。閉じるまで、検索語が空の間だけ出す（打てば結果に替わる）。閉じたことは SharedPreferences に覚える（索引とは別。更新では消えない）。

- アシスタントの設定は、`Settings.ACTION_VOICE_INPUT_SETTINGS` → `ACTION_MANAGE_DEFAULT_APPS_SETTINGS` → `ACTION_SETTINGS` の順に開けるものを開く。アシスタントの役割はアプリから頼めない（`roles.xml` で `requestable="false"`）
- Android 13 以上は「タイルを追加」で OS に頼める（`StatusBarManager.requestAddTileService`。権限は要らない）。12 以前は足し方の文だけ

## 画面の振る舞い

- アプリを選んだ時点で学習の判断と表示名を固定し、学習と起動の記録を裏のスレッドで保存する。保存を待つ間も主スレッドは塞がず、連打で同じ要求を重ねない
- 保存結果を受けてからアプリを開き、保存が両方とも成功していれば救済の Toast を出して、検索画面を閉じる。保存に失敗してもアプリを開き、Toast は出さず、失敗をログに残す
- OS が起動要求を拒んだ場合は「開けなかった」を出して索引を同期する。同じ検索画面なら閉じずに再試行を受け付ける。保存済みの選択は残す（理由は [learning.md](learning.md#アプリを開くときの保存r22026-11-14)）
- 保存中や OS に起動を渡す最中の `onStop` で、確定した学習の判断を失わない。呼び直し・回転で表示された検索画面は、古い要求の完了で閉じない
- アプリを開いて閉じた後、もう一度呼び出すと、空の検索語で開く
- 画面は 1 つにまとめる（`singleTask`）。アイコン・アシスタント・タイルのどの入口から呼び直しても、同じ画面が受けて、空の検索語・個人用・検索の結果に戻る。`singleTop` では、action の違う intent が届くと 2 つ目の画面が積まれるため（M3-03）
- 長押しの「アプリ情報」から「戻る」と、検索の画面に戻る（自分のプロファイルのアプリ）
- 検索画面は履歴画面に残さない
- 画面の端まで描く（Android 15 以降の target SDK では強制）。キーボードの高さに合わせて検索窓を上げる
- 縦向きを基本にし、横向き・タブレット・折りたたみでも崩れないことを確かめる。広い画面では、中身の幅を 640 dp までにして中央に置く（名前とスイッチ・索引・ボタンが離れすぎないように。M5-02）
- 検索語・表示中のタブ・すべてのアプリの表示・セッションは `SearchController`（AndroidX の ViewModel）に置き、回転などの構成の変更では保つ。セッションを終えるのは、構成の変更以外で画面を離れるとき・呼び直されるとき・アプリを選ぶとき。回転後も「おかね」→「paypay」の前の試行を救済に使える
- 現在の検索語は `SavedStateHandle` にも置き、プロセスの作り直しで戻す。入力の履歴・起動中の印は保存しない
- 救済の知らせと取り消し材料はプロセスの寿命で持つ。画面は未消費の知らせを読み、表示完了・入力による非表示・画面終了で表示分だけを消費する。回転では消費しない。取り消しの保存に失敗した場合も材料と未消費の知らせを保つ
- 「開いている最中」の印は同じ ViewModel に残す。保存中や OS へ渡す間に回転した画面は今回の知らせを表示・消費せず、次の検索のために残す。古い Activity への完了で作り直した画面を閉じない
- 学習のファイル操作の結果の表示は `LearnedListViewModel` に置く。操作と未消費の結果は画面終了後もプロセス内に残すので、回転中の完了と、閉じた後の完了を次の一覧へ渡せる

## 設定画面

入口は 2 つ: 検索語が空の間だけ検索窓の中に出す薄い歯車と、OS のアプリ情報（`ACTION_APPLICATION_PREFERENCES`。M5-01）。仕事用プロファイルを「混ぜる」ときは、一時停止の知らせを常に出す。

| 項目 | 内容 |
|---|---|
| 検索窓の位置 | 下（既定）／上。上のときは、切り替えと一時停止の知らせも上に寄せ、結果を上から並べる |
| 出た理由の表示 | 出す（既定）／出さない |
| 仕事用プロファイルのアプリ | 切り替えて検索する（既定）／個人用と混ぜて検索する／出さない |
| 学習 | 一覧・個別の削除・全消去・書き出し・読み込み |
| 起動の記録を消す | 確認後、個人用・仕事用の起動回数と最後に開いた時刻を全消去する。学習と設定は残す。削除後の起動は新しく記録する |
| 呼び出しの設定 | デジタルアシスタント・タイルの案内 |
| このアプリについて | 版、ソースの URL、使っている OSS のライセンス |

## 見た目とアクセシビリティ

- Material 3（Google の UI の設計の決まり）。Android 12 以降は壁紙に合わせた色（dynamic color）、それより前は既定の色。ダークテーマに対応する
- TalkBack（画面読み上げ）で、結果の行が「アプリ名、出た理由」と読まれる
- 文字の大きさを 200% にしても崩れない。押せる部分は 48 dp 以上
- 頭文字の索引は 1 字ずつが 48 dp に届かないので、全体を幅 48 dp の 1 つの部品（なぞって選ぶ帯）にする。TalkBack では索引を 1 つの項目として読ませ、見出しへ飛ぶ操作（「『か』へ移動」など）を操作の一覧に並べる。見出しの行は見出しとして読ませる（M5-02）
- 1 行に並べる短い項目の区切りは、言語ごとの文字列にする（日本語は「・」、英語は「 · 」）
- 画面の文字は日本語と英語
