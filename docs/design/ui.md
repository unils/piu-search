# 画面と操作

2026-10-27 の設計（保存・起動・画面の状態は 2026-11-14、R1・R2・R5 の実装に合わせて更新。索引の知らせと「索引の状態」は 2026-11-15 に 0.2.0 の設計を書いた）。

## 方針

- 開いたらすぐ打てる。キーボードは自動で出す
- 片手で使える。**検索窓は画面の下**（要件 U8・T3）。設定で上にも置ける
- 最も一致するアプリを、親指と検索窓に一番近い位置（検索窓のすぐ上）に置く。結果の一覧は下から上へ並べる
- 確定キー（IME の「検索」「実行」）で、一番上の候補（検索窓のすぐ上の候補）を開く
- 広告を出さない（U7）。通信もしない

## 検索画面

「ちず」と打ったときの画面を、上から順に書く。

| 位置 | 表示 |
|---|---|
| 画面の上部 | （結果が少ないときは空く） |
| 2 番目 | Yahoo!マップ　ジャンル: 地図 |
| 1 番目（検索窓の直上） | Google マップ　ジャンル: 地図（起動の回数が多いので上） |
| 検索窓 | ちず ✕ |
| 画面の下部 | キーボード |

- 1 行: アイコン・アプリ名・（必要なら）出た理由。理由は名前で一致しなかったときだけ小さく出す（「ジャンル: 地図」「学習」「読み: のりかえ」）。なぜ出たかがわかると、誤りに気づきやすく、学習を信用しやすい
- このアプリ自身は結果に出さない
- 検索語が空のとき: 「最近使ったアプリ」（4 件）と「よく使うアプリ」（8 件）を見出しつきで並べる。記録がなければ探し方の案内を出す。確定キーでは何も開かない（意図しない起動を避ける）
- 出た理由の書式: 「読み: …」「ローマ字: …」「別名: …」（別の言語の名前）「パッケージ名: …」「ジャンル: …」。名前で一致したときは出さない
- 一致がないとき: 「見つかりません」と、大きめの「すべてのアプリ」のボタンを出す
- 索引の更新が失敗しても、最後の索引で検索を続ける。アプリが検索に出ないか古いままになる失敗だけを、検索窓のそばに 1 行で小さく出す（[索引の知らせ](#索引の知らせ)）

### 索引の知らせ

索引（検索に使うアプリの一覧）の同期の失敗のうち、検索画面に出すのは次の 2 つだけ（出す・消す条件は [architecture.md](architecture.md#知らせ)）。アプリ 1 つの情報の一部（別の言語の名前・署名）が読めないことは出さない。一時的なものは自動で読み直され、決定的なものは利用者に打つ手がないため。それは設定の[索引の状態](#索引の状態)に出す。

| 条件 | 日本語 | 英語 |
|---|---|---|
| 同期全体の失敗（索引あり） | アプリの一覧を更新できませんでした。前の一覧で検索しています | Couldn't update the app list. Searching the previous one. |
| 同期全体の失敗（索引なし） | アプリの一覧を読めませんでした | Couldn't read the app list. |
| 個人用のプロファイルの失敗（仕事用があるとき） | 個人用のアプリの一覧を読めませんでした。前の一覧で検索しています | Couldn't read your personal apps. Searching the previous list. |
| 仕事用のプロファイルの失敗 | 仕事用のアプリの一覧を読めませんでした。前の一覧で検索しています | Couldn't read your work apps. Searching the previous list. |

- 0.1.x の「索引を更新できなかった」は、ほとんどのアプリを更新できていても出て、実態と違った。どの一覧が、どうなっているかを書く
- プロファイルが 1 つだけなら、プロファイルの失敗も同期全体と同じ文にする（「個人用」は仕事用があるときだけの言葉のため）。両方が失敗したら同期全体の文にする
- 1 行に出すのは 1 つだけ。同期全体の失敗を、プロファイルの失敗より先にする
- 行の末尾に「詳細」を付け、行全体を押せるようにする（高さ 48 dp 以上）。押すと設定の「索引の状態」を開く。TalkBack ではボタンとして読ませる
- 一時停止中の仕事用は失敗ではない。今までどおり一時停止の知らせを出す
- 設定の「仕事用プロファイルのアプリ」が「出さない」なら、仕事用のプロファイルの失敗は出さない（「索引の状態」にだけ出す）。仕事用を検索しない利用者には雑音のため

## すべてのアプリ

検索で出なかったアプリを学習させるには、全アプリから選べる必要がある（2026-10-27 のメンテナの提案）。

- 検索窓の横に「すべてのアプリ」のボタンを常に置く。結果の一覧の端に置くと、下から並べる一覧では画面の上端になり、親指が届かないため
- 押すと、全アプリを名前の順に並べる。英字で始まる名前は A〜Z の順で先にまとめ、かな・漢字の名前は**読みの五十音順**に並べる（漢字の名前も読みで並べられるのは、索引に読みがあるから）。右端に頭文字の索引（A〜Z、あ・か・さ…）を置き、なぞって飛べるようにする
- 個人用と仕事用を混ぜて出す設定のとき、仕事用の行は読み上げで「仕事用」と状態を添える（アイコンの印は読み上げに出ないため）。切り替えで仕事用を選んでいる間は全部が仕事用なので添えない
- 検索語は検索窓に残したまま一覧を出す。ここでアプリを開くと、その検索語とアプリを学習する（[learning.md](learning.md) の救済）。通常のアプリは学習と起動の記録の保存を待ってから開き、両方の保存と OS の受付が成功したら救済を Toast で短く知らせる。「「おかね」で PayPay を出すようにしました［取り消す］」は次に検索画面を開いたときに出す（[learning.md](learning.md#規則)）。何を覚えたかがわかり、誤りは取り消せる
- 検索窓に文字を打つと、検索の結果に戻る。「戻る」でも戻る。一覧を出している間はキーボードを下げ、確定キーでは何も開かない
- 一覧は上から読む向き（A が上）。数字・記号・ほかの文字で始まる名前と、読みのわからない漢字の名前は、最後の「#」にまとめる。名前の頭の記号は飛ばして見る（`+メッセージ` は「ま」の行）
- 五十音順は、濁点と小さい仮名を除き、長音を前の字の母音に置き換えた形で比べ、同じなら元の形で比べる（M3-02）

## 仕事用プロファイル

仕事用プロファイル（同じ端末の中で、仕事のアプリとデータを分けて持つ OS の仕組み）があるときだけ、検索窓の上に「個人用｜仕事用」の切り替えを出す（2026-10-27 のメンテナの希望）。

- 新しく開いたとき・入口から呼び直したときは「個人用」。回転などの構成の変更では選んでいるタブを保つ。検索の対象はそのとき選んでいるプロファイルのアプリだけ
- 個人用で一致がなく、仕事用に一致があるときは「仕事用に 2 件」と知らせ、押すと切り替わる
- 仕事用の結果のアイコンには、OS の標準の印（かばん）を付ける
- 仕事用アプリを一時停止しているときは、そのことを表示する。一時停止中のアプリを開こうとすると、OS が「仕事用アプリを再開しますか」の確認を出し、再開したらそのまま開く（AOSP の `ActivityStartInterceptor.interceptQuietProfileIfNeeded`）。このアプリの側で再開の操作はできない（既定のホームアプリにしか許されない）。確認で取り消したかを受け取れないため、一時停止中への要求は起動回数と学習に記録しない（[learning.md](learning.md#アプリを開くときの保存r22026-11-14)）
- 自分以外のプロファイルは、すべて仕事用として扱う（仕事用かを見分ける API はシステムのアプリにしか使えない。OEM の複製のプロファイルなども「仕事用」にまとまる）
- 学習はプロファイルごとに分ける（個人用の LINE と仕事用の LINE は別のアプリとして扱う）
- GrapheneOS の「別のユーザー」とプライベートスペースのアプリは、OS の仕様で見えない

## 長押しのメニュー

- アプリ情報（OS の設定画面のそのアプリのページ）
- この語では出さない（学習の R4）
- この語での学習を消す（学習で出ている場合）
- 学習の一覧（どの行にも出す。誤って覚えた行からすぐ直しに行けるので、設定画面ができた後も残す。一覧は検索の画面と同じタスクに積み、「戻る」で検索の画面に戻る）

アンインストールは入れない（`REQUEST_DELETE_PACKAGES` の権限が要る）。アプリ情報の画面から行える。

## 呼び出し

| 入口 | 動き |
|---|---|
| ランチャーのアイコン | 検索画面を開く |
| デジタルアシスタント | 設定で既定のアシスタントにすると、画面の隅からのスワイプや電源ボタンの長押しで開く（Pixel での動作は実機で確認する） |
| クイック設定タイル | 通知の領域を下ろして開く |

初回の起動時に、デジタルアシスタントとタイルの設定の仕方を 1 枚で案内する（OS の設定画面を開くボタン付き）。強制はしない。閉じるまで、検索語が空の間だけ出す（打てば結果に替わる）。閉じたことは SharedPreferences に覚える（索引とは別。更新では消えない）。

- アシスタントの設定は、`Settings.ACTION_VOICE_INPUT_SETTINGS` → `ACTION_MANAGE_DEFAULT_APPS_SETTINGS` → `ACTION_SETTINGS` の順に開けるものを開く。アシスタントの役割はアプリから頼めない（`roles.xml` で `requestable="false"`）
- Android 13 以上は「タイルを追加」で OS に頼める（`StatusBarManager.requestAddTileService`。権限は要らない）。12 以前は足し方の文だけ

## 画面の振る舞い

### アプリを開くとき

選んだ時点で学習の判断・表示名・時刻を固定し、通常の要求は起動の記録と学習を裏のスレッドで保存する。保存中も画面は固まらず、連打で同じ要求を重ねない。

学習と起動の記録は 1 つの頼み・1 つのトランザクションで保存し、その結果を待ってから起動する。保存の成功と OS の受付の後にだけ救済の Toast を出す。保存失敗でも起動は続け、失敗はログに残す（学習も起動の記録も書かれない。片方だけが書かれることはない）。起動すると画面は閉じるので、次に検索画面を開いたとき、検索窓の下に「前に選んだ記録を保存できなかった」を小さく出す（次の保存が成功したら消える）。受理した起動（保存と OS への要求）は、画面を閉じても最後まで行う。一時停止中の仕事用アプリは保存せず、OS の再開確認へ渡す。

OS が起動を拒んだら「開けなかった」を出し、索引を同期する。同じ検索画面が表示中なら新しいセッションで再試行を受け付ける。非表示なら、入力の記録と漢字の読みは復帰まで再開しない。保存済みの記録は残す（[learning.md](learning.md#アプリを開くときの保存r22026-11-14)）。

起動が受け付けられたら元の検索画面を閉じる。保存中や OS へ渡す間に呼び直し・回転があっても、固定した判断は変えず、古い完了で新しい画面を閉じない。起動中の印は旧 Activity が破棄済みでも解除し、戻った画面で別のアプリも選べる。

### 記録の DB を作り直したとき

記録の DB（`piu.db`）が壊れていると SQLite が知らせたら、記録の書き手は DB を消して新しく始める。そのことを、次に検索画面を開いたとき 1 回だけ、「前に選んだ記録を保存できなかった」と同じ場所に控えめに出す。その画面では検索語を打ち始めるまで出す。知らせる前にプロセスが終わっても、印はファイルに残るので次の起動で出る。

| 日本語 | 英語 |
|---|---|
| 記録を読めなかったため、学習と起動の記録を新しく始めました | Your learning and launch records couldn't be read, so they were started over |

### 回転とセッション

| 出来事 | 検索語・表示 | セッションと知らせ |
|---|---|---|
| 新規の起動・入口からの呼び直し | 空の検索語・個人用・検索の結果 | 新しいセッションを始める |
| 回転などの構成の変更 | 検索語・タブ・全アプリ一覧の表示を保つ | 同じ ViewModel のセッションを続け、前の試行も救済に使う |
| ホームや別の画面へ移る | 戻ったときの表示は保つ | 入力履歴を捨て、復帰時に新しいセッションを始める |
| アプリを選ぶ | 選んだ時点の判断を固定する | セッションを終え、今回の救済の知らせは次の検索まで保留する |
| プロセスの作り直し | `SavedStateHandle` から現在の検索語だけを戻す | 入力履歴・起動中の印・未消費の知らせは戻さない |

検索語・タブ・セッション・起動中と知らせの保留の印は `SearchViewModel` が持つ。起動中の印と知らせの保留は別にし、起動の完了後も、回転した画面では今回の知らせを表示・消費しない。6 秒以上過ぎても次の検索で取り消せる。

救済の知らせと取り消し材料はプロセス内の記録の書き手（`RecordsActor`）が持つ。画面は記録の写しの流れから未消費の知らせを読み、表示完了・入力による非表示・画面終了で表示分だけを消費する。回転では消費しない。取り消しの保存失敗では材料と知らせを残す。同じ組の新しい保存が成功したら、古い取り消しは無効になる。

### 画面の呼び出しと配置

- 検索画面は `singleTask` にまとめる。アイコン・アシスタント・タイルのどこから呼び直しても同じ画面が受け、空の検索語・個人用・検索の結果に戻す。アプリを開いて閉じた後も、次は空の検索語で始める
- 長押しの「アプリ情報」や設定・学習の一覧から「戻る」と、検索画面に戻る。自分のプロファイルのアプリ情報は同じタスクに積む
- 検索画面は履歴画面に残さない
- 画面の端まで描き、キーボードの高さに合わせて検索窓を上げる
- 縦向きを基本にし、横向き・タブレット・折りたたみでも崩れないようにする。広い画面では中身を幅 640 dp までにして中央に置く

### 学習の操作結果

検索画面での抑制・削除・取り消し、検索開始時の記録の読み込み・忘却の失敗は Toast で知らせる。学習一覧では、読み込み・削除・全消去・ファイル操作の失敗を Snackbar で知らせる。保存に失敗した変更は一覧や検索へ反映しない。起動前の保存失敗の扱いは[上記](#アプリを開くとき)のとおり。

学習一覧の結果の表示状態は `LearnedListViewModel` に置く。操作と未消費の最新の結果はプロセス内に残す。回転中に完了した結果も、画面を閉じた後に完了した結果も、次の一覧で知らせる。プロセスが終わると未表示の結果は消える。

## 設定画面

入口は 2 つ: 検索語が空の間だけ検索窓の中に出す薄い歯車と、OS のアプリ情報（`ACTION_APPLICATION_PREFERENCES`。M5-01）。仕事用プロファイルを「混ぜる」ときは、一時停止の知らせを常に出す。

| 項目 | 内容 |
|---|---|
| 検索窓の位置 | 下（既定）／上。上のときは、切り替えと一時停止の知らせも上に寄せ、結果を上から並べる |
| 出た理由の表示 | 出す（既定）／出さない |
| 仕事用プロファイルのアプリ | 切り替えて検索する（既定）／個人用と混ぜて検索する／出さない |
| 学習 | 一覧・個別の削除・全消去・書き出し・読み込み |
| 起動の記録を消す | 確認後、個人用・仕事用の起動回数と最後に開いた時刻を全消去する。学習と設定は残す。削除後の起動は新しく記録する |
| 呼び出しの設定 | デジタルアシスタント・タイルの案内 |
| 索引の状態 | 索引のアプリの数と、読めなかった情報の件数を 1 行で出し、押すと[詳しい画面](#索引の状態)を開く（例:「182 個のアプリ・問題なし」「182 個のアプリ・1 件の情報を読めていません」） |
| このアプリについて | 版、ソースの URL、使っている OSS のライセンス |

### 索引の状態

索引が今どうなっているかを、隠さずに見せる画面。報告に使う文をコピーできる。設定の項目から開き、検索画面の知らせの「詳細」からも開く。開いたら同期を頼み、終わったら表示を新しくする（設定から開いたときは、このプロセスでまだ同期していないことがあるため）。

上から次の順に並べる。件数が 0 の項目も「なし」と出して残す。問題がないことも見えるようにするため。

| 順 | 項目 | 中身 |
|---|---|---|
| 1 | 概要 | 索引のアプリの数（仕事用があれば個人用・仕事用に分ける）、最後に更新した時刻（`index.db` に最後に保存できた時刻）、このプロセスの最後の同期の結果（下の表） |
| 2 | アプリの一覧 | プロファイルごとに「読めました」「一時停止中」「読めませんでした」 |
| 3 | ジャンルの判定 | 「判定できました」か「判定できませんでした（前のジャンルで検索しています）」 |
| 4 | 読めていない情報 | 区分ごとの件数と、アプリの一覧（下記） |
| 5 | 報告 | 「報告用の文を見る」のボタンと、issue のページへのリンク。リンクの横に「報告する前に、同じ報告がないか確かめてください」と書く。連絡先は issue だけで、メールの宛先は載せない（メンテナの判断、2026-11-15） |

最後の同期の結果（規則は [architecture.md](architecture.md#知らせ)）:

| 結果 | 日本語 | 英語 |
|---|---|---|
| `OK` | 更新できました | Updated |
| `ISSUES` | 更新できました（一部の情報を読めていません） | Updated; some information is missing |
| `PARTIAL` | 一部を更新できませんでした | Partly not updated |
| `FAILED` | 更新できませんでした | Not updated |
| （まだ同期していない） | まだ更新していません | Not updated yet |

アーカイブ済みのアプリ（Android 15 以降。APK を消してデータを残した状態）は、欠けとして出さない。概要に「うちアーカイブ済み N 個」とだけ出す。件数は保存した索引から数えるので、一時停止中の仕事用の分も入る（[architecture.md](architecture.md#失敗の分け方)）。

区分ごとの件数を、不具合の疑い → 一時的 → 決定的の順に出す。一時的は 1 つの区分にし、そのうち次の更新で読み直す件数を添える（例:「一時的に読めないもの: 2 件（うち次の更新で読み直す 1 件）」。2026-11-16 の管理役の判断。区分は理由の型で決まり、読み直すかは印で決まる別の事実なので、区分の数を印で割らない）。

読めていない情報の一覧は、区分の順（不具合の疑い → 一時的で読み直しを待つ → 一時的で読み直した → 決定的）、同じ区分の中は表示名の順に並べる。1 行に出すもの:

- 表示名と、仕事用なら「仕事用」
- パッケージ名
- 読めていない情報・区分・影響。例:「別の言語の名前・読めないまま使っているもの。英語の名前では出ません」
- 理由（例外の型）と、初めて読めなかった日

区分の言葉は保存せず、表示のときに理由（と再試行の印）から引く（[architecture.md](architecture.md#材料の欠け)）。

| 区分 | 条件 | 日本語 | 英語 |
|---|---|---|---|
| 不具合の疑い | 理由が不具合の疑い | Piu Search の不具合の疑い | Possible bug in Piu Search |
| 一時的 | 理由が一時的 | 一時的に読めないもの | Temporarily unreadable |
| 決定的 | 理由が決定的 | 読めないまま使っているもの | Used without this information |

一時的の行には、再試行の枠（最後の試みの `retry`）から引いた言葉を区分に続ける。立っていれば「次の更新で読み直します」（Will retry on the next update）、下りていれば「読み直しても読めませんでした」（Still unreadable after a retry）。

| 段 | 日本語 | 英語 | 影響 |
|---|---|---|---|
| `ENTRY` | アプリの情報 | App information | 前の情報で検索しています。新しく入れたアプリなら、名前でだけ出ます |
| `LABEL` | 別の言語の名前 | Names in other languages | その言語の名前では出ません |
| `SIGNER` | 提供元（署名） | Developer (signature) | 提供元の名前では出ません |
| `KEYS` | 検索の語の作成 | Search terms | 前の情報で検索しています。新しく入れたアプリなら、名前の文字どおりでだけ出ます |

#### 報告用の文

「報告用の文を見る」を押すと、コピーする文をそのまま全部見せる画面（全画面の窓）を開き、「コピー」と「閉じる」を置く。**見せる文とコピーする文は同じもの**にする。利用者が貼る前に、何が入っているかを確かめられるようにするため。窓の上に「アプリのパッケージ名と、端末の製造元・機種・OS の版が入ります。仕事用のアプリのパッケージ名からは、勤め先が分かることがあります。Piu Search はこれを送信しません。貼る前に確かめ、出したくない行は消してください」と書く。

- コピーは `ClipboardManager` に入れるだけで、送らない（`INTERNET` の権限がない）
- Android 13 以上は OS がコピーしたことを画面に出すので、自分では知らせない。12 以前だけ「コピーしました」を Toast で出す（[公式の文書](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste)の「Avoid duplicate notifications」。2026-11-15 確認）
- 文は、画面の言語によらず英語の固定の書式にする。メンテナが言語によらず読め、行ごとに比べられるようにするため
- 日付は UTC の `YYYY-MM-DD` までにする。時刻と端末の時間帯は入れない。時刻は利用者がいつ検索を開いたかを表し、報告には「いつから欠けているか」で足りるため
- 端末の製造元と機種（`Build.MANUFACTURER`・`Build.MODEL`）を入れる（メンテナの判断、2026-11-15）。`Build.FINGERPRINT` にも機種の符号は入るが、販売名でないので、`device` の行で読みやすくする
- 表示名と例外のメッセージは入れない。表示名は端末の言語で変わり、パッケージ名で足りる。メッセージにはパスなどが入りうる
- `KEYS` の不具合の疑いの行には、表示名の代わりに、欠けの行の `input_summary`（例外が起きた入力の種類・長さ・文字種）を入れる。Play にないアプリではメンテナが入力を知りえないため。長さと文字種では人もアプリも特定できない。失敗したときに保存した値を使い、今の索引から作り直さない（旧索引の行を保った組では、今の表示名は失敗したときの入力と違う）
- 各行に、その組が system のアプリか・APEX の中の APK か・split の数・鍵があるかを入れる。0.1.0 の不具合（APEX の中の APK だけで起きた）と同じ型を、報告から見分けるため。パスは入れない（パスの乱数の部分は端末ごとに違い、識別子に近い）。これらは報告の文を作るときに `LauncherApps` から読み、読めなければ `?` にする
- 不具合の疑いの行には、失敗した試みの版（`ver=`、欠けの版）と、例外の先頭 5 フレームを続けて書く（R8 で変わった名前のまま。行の番号は残る。メンテナがその版の `mapping.txt` で戻す）
- 読めていない情報が 200 件を超えたら、200 件で切り、残りの件数を書く

書式（値は例）:

```
Piu Search index status
app: 0.2.0 (5)
android: 15 (API 35)
device: <製造元> <機種>
build: <Build.FINGERPRINT>
locales: ja-JP,en-US
index: personal=182 work=40 archived=3
last saved: 2026-11-15
last sync: result=ISSUES
profiles: personal=COMPLETE work=UNAVAILABLE
genres: OK
issues: transient=0 retry=0 deterministic=1 bug=1
- DETERMINISTIC LABEL work com.example.app cause=android.content.res.Resources$NotFoundException system=N apex=N splits=0 key=Y since=2026-11-14 last=2026-11-15
- BUG KEYS personal com.example.other cause=java.lang.IllegalArgumentException system=N apex=N splits=2 key=Y input=label:len42:kanji,kana ver=5 since=2026-11-15 last=2026-11-15
    at a.b.c(SourceFile:12)
    at a.b.d(SourceFile:40)
```

`last saved` は最後に保存できた同期の日。`last sync` はこのプロセスの最後の同期で（保存した索引の一覧の状態は前のプロセスの結果を含むので、このプロセスで同期が終わるまでは `none`）、`result` は上の表の `OK`・`ISSUES`・`PARTIAL`・`FAILED`。まだ同期していなければ `last sync: none`。`profiles` の値は `COMPLETE`・`UNAVAILABLE`・`FAILED`。プロファイルはシリアル番号ではなく `personal`・`work`（2 つ目からは `work2`…）で書く。行の先頭の区分（`TRANSIENT`・`DETERMINISTIC`・`BUG`）は、文を作るときに理由から引いたもの。`TRANSIENT` の行には、`cause` の後に再試行の印（`retry=Y`・`retry=N`）を書く。`issues` の `retry` は `transient` の内数。行は区分・プロファイル・パッケージ名の順に並べる（表示名を入れないため）。

## 見た目とアクセシビリティ

- Material 3（Google の UI の設計の決まり）。Android 12 以降は壁紙に合わせた色（dynamic color）、それより前は既定の色。ダークテーマに対応する
- TalkBack（画面読み上げ）で、結果の行が「アプリ名、出た理由」と読まれる
- 文字の大きさを 200% にしても崩れない。押せる部分は 48 dp 以上
- 頭文字の索引は 1 字ずつが 48 dp に届かないので、全体を幅 48 dp の 1 つの部品（なぞって選ぶ帯）にする。TalkBack では索引を 1 つの項目として読ませ、見出しへ飛ぶ操作（「『か』へ移動」など）を操作の一覧に並べる。見出しの行は見出しとして読ませる（M5-02）
- 1 行に並べる短い項目の区切りは、言語ごとの文字列にする（日本語は「・」、英語は「 · 」）
- 画面の文字は日本語と英語
